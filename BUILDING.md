# Building Cyber Jum into a real .gba ROM

Step-by-step instructions for macOS (Apple Silicon) with Homebrew, assuming
nothing is installed yet. Every command goes in Terminal, run from this
project's directory unless noted.

## 1. Install the Rust toolchain

```sh
brew install rustup
```

Homebrew puts rustup's binaries in `/opt/homebrew/opt/rustup/bin`, which is
**not** on your PATH by default. Add it (plus cargo's own bin directory,
used in step 3) to your shell profile:

```sh
echo 'export PATH="/opt/homebrew/opt/rustup/bin:$HOME/.cargo/bin:$PATH"' >> ~/.zprofile
source ~/.zprofile
```

Now install nightly Rust with the `rust-src` component:

```sh
rustup toolchain install nightly --component rust-src
```

Why nightly + rust-src? The GBA's CPU target (`thumbv4t-none-eabi`) is a
"tier 3" Rust target: no prebuilt standard library exists, so cargo compiles
`core` and `alloc` from source on the fly (`build-std`), which is a
nightly-only feature. This project's `rust-toolchain.toml` pins nightly
automatically, so plain `cargo` commands just work once it's installed.

## 2. Build the game

```sh
cargo build --release
```

The first build takes a few minutes (it compiles the Rust core library and
the agb engine); later builds take seconds. The result is an ELF executable
at:

```
target/thumbv4t-none-eabi/release/cyber_jum
```

No external ARM toolchain is needed — agb links with Rust's built-in LLD
using its own GBA linker script.

## 3. Convert the ELF into a .gba ROM

Real hardware (and some emulators) need a plain ROM image with a valid
cartridge header — the entry branch, the Nintendo logo bitmap, and a header
checksum. agb's `agb-gbafix` tool does this:

```sh
cargo install agb-gbafix         # one-time install
agb-gbafix target/thumbv4t-none-eabi/release/cyber_jum -o cyber_jum.gba
```

`cyber_jum.gba` (~1.1 MB, mostly music data) is the finished cartridge
image. It runs in any GBA emulator and, via a flash cart, on real hardware.

## 4. (Optional) regenerate the assets

All PNG art and WAV audio is generated by Python scripts, managed with
[uv](https://docs.astral.sh/uv/):

```sh
brew install uv
cd tools/asset_gen
uv run python generate_art.py
uv run python generate_audio.py
```

Then rebuild (step 2) — the assets are baked into the ROM at compile time.

## Troubleshooting

| Symptom | Fix |
|---|---|
| `rustc: command not found` | The PATH line from step 1 isn't active in this shell — `source ~/.zprofile`. |
| `error[E0463]: can't find crate for 'core'` | `rust-src` is missing: `rustup component add rust-src --toolchain nightly`. |
| `error: "...gba.ld" no such file` | You're building outside the project directory; `.cargo/config.toml` must be picked up from the project root. |
| Emulator shows a white screen | You ran the raw ELF in an emulator that needs a fixed ROM — use the `.gba` from step 3 (mGBA happily runs the ELF directly, though). |
